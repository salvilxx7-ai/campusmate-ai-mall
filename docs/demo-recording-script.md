# CampusMate 产品演示录屏脚本

## 录制目标与原则

本脚本用于录制一段约 **4–5 分钟** 的真实产品操作视频。录制时应使用当前运行中的 CampusMate 页面和真实按钮，不应以剪辑、伪造弹窗或手工改写指标代替系统行为。视频开头和结尾都应说明：商品、订单、工单、图片与规则为模拟数据，系统不处理真实支付、物流或真实客服。

| 录制前准备 | 操作 |
|---|---|
| 账号 | 准备一个普通用户会话和一个管理员会话；录制前确认管理员可访问“管理台”“质量监控”“系统状态”。 |
| 目录 | 保留若干已上架商品；如需演示审核，准备一件 `pending_review` 商品。 |
| 网络与窗口 | 使用桌面窗口录制；关闭无关浏览器标签、通知与含个人信息的页面。 |
| 信息安全 | 不展示浏览器 Cookie、环境变量、终端凭据、邮箱收件箱或任意真实个人数据。 |
| 质量检查 | 录制前依次运行 `pnpm test:all`、`pnpm check` 和生产构建；视频里无需展示整段终端输出。 |

## 录制分镜与口播

| 时间 | 页面与操作 | 建议口播 | 必须展示的事实 |
|---:|---|---|---|
| 00:00–00:25 | 首页。展示模拟数据披露、搜索框和 AI 客服入口。 | “CampusMate 是校园闲置流转与规则咨询系统。当前商品、订单和规则均为模拟数据，不含支付或真实售后。” | 数据披露、商品发现入口。 |
| 00:25–00:50 | 进入“全部商品”，搜索“教材”，打开一件商品。 | “公开目录只展示已上架商品。访客可以搜索和浏览，但下单相关操作需要登录。” | 搜索、分类或商品详情。 |
| 00:50–01:25 | 以普通用户登录，进入“发布管理”或“发布闲置物品”。展示提交物品后的审核状态，或展示现有记录的编辑/撤回/重新提交。 | “发布图片由服务端校验并保存引用；新商品默认等待审核，不会直接出现在公开目录。编辑已上架商品会重新进入审核。” | `pending_review`、编辑/撤回/重新提交之一。 |
| 01:25–01:50 | 打开“个人中心”，展示我的订单、发布状态和工单进度。 | “订单、发布记录和工单都由当前登录会话聚合；用户不能通过前端参数查看其他账户的数据。” | 个人中心模块与当前账户范围。 |
| 01:50–02:25 | 打开“AI 客服”，输入“什么商品不能上架？”。再输入无关问题，例如“星际旅行需要带什么？”。 | “规则问题先检索公开资料，回答携带来源；缺少依据时系统不会编造规则，而是提示人工支持。” | 引用来源、低置信提示或人工支持入口。 |
| 02:25–03:05 | 切换到管理员，打开“管理台”的商品审核队列。按状态筛选，打开一条“查看”详情。 | “管理员可以按状态筛选并批量审核。单件抽屉显示图片、说明、必要发布者上下文和商品范围的追加式审核历史。” | 筛选标签、详情抽屉、审核原因或历史。 |
| 03:05–03:30 | 选择待审核商品，展示批量通过或填写原因后的批量拒绝流程。 | “服务端逐条锁定并复核状态；结果区分通过、拒绝和跳过，避免过期页面误审其他状态。” | 复选框、拒绝原因输入、批量操作按钮。 |
| 03:30–04:05 | 打开“系统状态”。 | “系统状态集中展示 FastAPI Agent、Embedding、Chroma 片段和规则索引统计。冷启动或索引失败会明确标为需要关注，而不会伪造健康状态。” | Python Agent、规则文档、已同步索引、状态标识。 |
| 04:05–04:30 | 打开“质量监控”，展示固定检查入口与指标；返回服务说明页收尾。 | “质量检查记录意图、来源、拒答和耗时，用于发现规则或服务更新后的异常。技术和需求资料已随仓库交付。” | 质量监控指标、服务说明的数据披露。 |

## 录制完成检查

视频应清楚呈现“用户发现商品 → 用户发布/个人数据隔离 → 规则咨询 → 管理员审核追溯 → 系统状态”的闭环。导出前检查音频是否清楚、鼠标停留是否足够、文本是否可读；建议导出为 `docs/assets/campusmate-demo.mp4` 的本地副本，但不将原始录像或包含私人信息的素材直接提交到仓库。

> 如果没有待审核商品，可先用普通用户完成一次发布，再切换管理员审核；若 Agent 正在冷启动，先在系统状态页等待“Python Agent 可用”后再开始正式录制。
