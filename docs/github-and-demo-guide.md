# CampusMate GitHub 发布与录屏指南

## GitHub 发布前检查

发布前应确认仓库只包含源代码、数据库迁移、公开来源说明和明确标注的演示数据。请不要提交 `.env`、访问令牌、真实简历、个人订单、真实校方内部文件、未经授权的图片或录屏原片。请保留 `README.md` 中对参考商城和 UI/UX Skill 的 MIT 许可归属说明。

| 检查项 | 应达到的状态 |
|---|---|
| `pnpm test` | 全部通过。 |
| `pnpm check` | TypeScript 无错误。 |
| 演示披露 | 首页、商品、订单和客服中明确标注模拟/演示边界。 |
| 来源声明 | README、项目说明页和知识库文档可追溯到公开 URL。 |
| 安全检查 | 无密钥、无真实个人数据、无伪造评价、无真实支付承诺。 |
| 展示数据 | 录屏前运行一次固定评测，使面板显示实际运行结果。 |

## 建议的 GitHub 提交顺序

建议先创建私有仓库核对环境和内容，再决定是否公开。首个公开提交应包含功能代码、迁移、文档和测试；后续提交分别围绕“商城与订单”“RAG 与 Agent”“评测与文档”组织，便于面试时复盘开发过程。提交信息应说明动机，例如 `feat: add grounded customer service with citations`，不要只写 `update` 或 `fix`。

## 3–5 分钟录屏脚本

| 时间 | 操作 | 讲述重点 |
|---|---|---|
| 00:00–00:25 | 展示首页与商品分类。 | “项目从校园二手交易出发，但核心目标是展示可信 AI 客服与权限边界。” |
| 00:25–00:55 | 搜索“教材”，进入商品详情。 | “商品与价格均为演示数据；公开浏览与登录后下单分离。” |
| 00:55–01:25 | 登录并创建模拟订单，进入订单页。 | “订单只按服务端当前会话查询；前端不传用户 ID。” |
| 01:25–02:15 | 进入 AI 客服，问一条规则问题。 | “先 TF-IDF 检索，再让模型基于片段回答；引用区显示证据与公开来源。” |
| 02:15–02:40 | 询问无关问题。 | “低分检索不会让模型猜测，系统会转人工。” |

| 03:10–03:40 | 运行固定评测。 | “指标来自本次 `evaluationRuns`，不手填；覆盖规则、无匹配、商品、本人订单和跨账户订单。” |
| 03:40–04:10 | 打开项目说明页。 | “这里可对应代码讲清楚 RAG、审计、角色校验和受管 TiDB 不支持触发器时的诚实取舍。” |

## 录屏注意事项

录制时不要遮掩“演示数据”“非正式校方政策”等提示。若评测分数不是 100%，应保留真实结果，并说明原因和下一步优化方案；比起人为美化，这更能体现工程判断。录制前可使用无痕窗口检查普通用户是否看不到管理员入口，并在屏幕上避免出现个人邮箱、浏览器书签、密码管理器或任何令牌。

## 面试追问速答

> **问：为什么不把 RAG 直接交给模型？**
>
> **答：** 模型只在检索到证据后负责压缩与表达。证据阈值与引用返回由程序控制，因此可以解释“为什么回答”“引用了什么”和“为什么拒答”。

> **问：为什么普通用户看不到后台还不够？**
>
> **答：** 前端入口可以被绕过。管理员 API 使用服务端 `adminProcedure`，普通用户构造请求同样会收到 `FORBIDDEN`；测试也覆盖该边界。

> **问：TF-IDF 的局限是什么？**
>
> **答：** 它更依赖词面匹配，无法像语义 Embedding 一样理解近义表达。首版选它是为了零外部依赖、结果可复现和便于面试解释；后续可保留分块与引用链路，替换向量生成器为 Embedding 服务。
