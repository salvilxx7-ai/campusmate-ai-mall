# CampusMate 产品需求文档

## 1. 背景、目标与边界

CampusMate 是一个面向校园闲置物品流转的模拟交易与规则咨询系统。用户能够发现商品、登录后创建模拟订单、发布闲置物品、管理本人资料和工单；管理员能够审核商品、管理规则知识库、处理模拟工单、管理角色并查看服务质量与系统状态。产品的核心目标是把“可浏览、可咨询、可追溯、可管控”的业务闭环落实到页面、服务端权限和数据记录中。

> **数据说明：** 当前环境中的商品、图片、订单、工单与规则均为明确标注的模拟数据。系统不处理真实支付、物流、资金托管、真实人工客服或真实售后裁定；规则资料仅根据公开 C2C 信息改写。[1] [2] [3]

| 角色 | 主要目标 | 可执行范围 | 不可执行范围 |
|---|---|---|---|
| 访客 | 发现校园闲置商品和了解规则服务。 | 浏览公开商品、搜索和分类筛选。 | 查看待审核商品、个人订单、工单或后台。 |
| 普通用户 | 完成模拟交易、发布闲置物品并取得规则帮助。 | 管理本人资料、订单、发布物品和工单；使用 AI 客服。 | 查看他人订单、工单、发布管理记录或管理员数据。 |
| 管理员 | 维护目录、规则与服务质量。 | 审核商品、管理知识文档/工单/角色、查看系统状态与审核历史。 | 读取密钥、Cookie 或不相关的私密业务数据。 |

## 2. 需求范围与验收标准

| 编号 | 功能需求 | 关键业务规则 | 可验收结果 |
|---|---|---|---|
| PRD-01 | 商品发现。 | 公开目录和详情只展示 `active` 商品。 | 访客可搜索、筛选、浏览分类与详情；非公开状态不通过 URL 暴露。 |
| PRD-02 | OAuth 身份与权限。 | 身份由服务端会话获取，角色由服务端程序校验。 | 普通用户直接调用管理员过程得到拒绝；管理员功能不依赖菜单隐藏。 |
| PRD-03 | 模拟订单。 | 订单归属由当前会话决定，订单项保存标题与价格快照。 | 用户只能看到本人订单；越权读取被拒绝并记录审计。 |
| PRD-04 | 发布与审核。 | 图片限 1–3 张 JPEG/PNG/WebP、单图 2MB；新商品为 `pending_review`。 | 发布后不进入公开目录；编辑重新审核；拒绝/撤回可重新提交。 |
| PRD-05 | 个人中心与工单。 | 资料、订单、发布记录和工单都按当前用户隔离。 | 用户可查看本人轨迹和编辑独立资料，不能修改角色或 OAuth 身份信息。 |
| PRD-06 | 规则客服。 | 规则回答必须带公开来源；证据不足时不能编造结论。 | 规则问答返回来源片段；无依据时提示覆盖不足或人工支持。 |
| PRD-07 | 受控业务工具。 | 商品、订单和工单工具由 Node 网关在会话校验后执行。 | Python RAG 运行时不获得订单、Cookie、用户身份或数据库凭据。 |
| PRD-08 | 管理员运营。 | 审核按状态机处理；拒绝必须说明原因；批量处理逐项锁定。 | 批量结果区分通过、拒绝和跳过，且为每项写入审计。 |
| PRD-09 | 系统可观测性。 | 系统状态只呈现运行与索引指标，审核详情只呈现必要数据。 | 管理员可查看 Agent 健康、索引统计和商品审核历史，不能借此导出密钥或邮箱。 |

## 3. 主业务流程

### 3.1 发现商品到模拟订单

访客在首页或商品列表搜索、筛选公开商品。打开详情时，服务端再次验证商品处于 `active`；用户登录后发起模拟下单，服务端从会话获取买家 ID，在事务中创建订单与订单项快照，并将商品更新为 `reserved`。订单列表和详情始终以当前会话用户为查询条件，跨账户尝试会被拒绝并写入追加式审计记录。

### 3.2 发布物品到审核闭环

用户在发布页提交分类、标题、价格、成色、描述和图片。浏览器负责交互提示，Node 服务端再次检查字段、MIME 和体积；图片字节写入对象存储，数据库只保存引用。商品进入 `pending_review`，管理员在审核队列逐项或批量通过/拒绝。发布者编辑已上架商品后会重新进入审核；撤回转为 `archived`；已拒绝或已撤回的商品可重新提交；`reserved` 商品不可编辑或撤回。

| 状态 | 发布者操作 | 管理员操作 | 公开可见性 |
|---|---|---|---|
| `pending_review` | 编辑、撤回。 | 通过或拒绝。 | 否。 |
| `active` | 编辑、撤回。 | 状态维护。 | 是。 |
| `reserved` | 不可编辑、不可撤回。 | 按订单流处理。 | 否。 |
| `archived` | 编辑、重新提交。 | 状态维护。 | 否。 |
| `rejected` | 查看原因、编辑、重新提交。 | 再次审核。 | 否。 |

### 3.3 规则咨询到人工支持记录

客服先识别规则问答、商品搜索、本人订单和人工支持意图。公开规则问题只将文本发送至 FastAPI/LangGraph/Chroma，返回来源和置信度结果；商品和订单工具仍由 Node 网关执行。未登录用户查询订单会得到登录提示；跨账户请求会被拒绝；用户明确提出人工支持时，登录状态下可创建仅本人可见的模拟工单。

### 3.4 管理员规则运营与系统状态

管理员上传具备 HTTPS 公开来源的 `.md` 或 `.txt` 规则文件。Node 保存原文、指纹、分块、版本与向量状态，Python 对公开内容进行语义向量化；MySQL/对象存储是事实源，Chroma 是可重建的派生索引。管理员可在系统状态页查看 FastAPI 健康、Embedding、索引版本、规则文档/分块、生命周期和向量同步统计；发生失败或冷启动时，界面明确提示，不把旧状态伪装为当前成功。

## 4. 非功能要求

| 类别 | 当前要求 | 约束和处理 |
|---|---|---|
| 安全 | 权限在服务端二次验证；重要允许/拒绝路径追加审计。 | 数据库环境无触发器，审计由应用层策略约束；应用不提供审计更新/删除过程。 |
| 数据最小化 | Python 只处理公开问题；审核详情不返回邮箱。 | 系统状态不返回密钥、Cookie、订单或其他账户数据。 |
| RAG 可信性 | 公开规则回答带来源，低置信拒答或提示人工支持。 | Chroma 为容器本地派生索引，不能替代 MySQL/对象存储事实源。 |
| 可用性 | Node 对 Python 失败有受控 TF-IDF/余弦回退。 | 不承诺真实生产 SLA、真实支付可用性或容量指标。 |
| 可维护性 | 服务、页面、测试和文档共同演进。 | 每次功能变更同步技术交付、业务流程和工程日志。 |

## 5. 验证与交付

当前交付版本通过 **72 项 TypeScript 测试** 与 **7 项 Python Agent 测试**，覆盖订单隔离、审计策略、发布状态机、图片校验、批量审核、角色门槛、RAG、工具权限、规则同步、系统状态和审核历史。执行 `pnpm test:all`、`pnpm check` 与 `NODE_OPTIONS=--max-old-space-size=1280 pnpm build` 可复核当前测试、类型和构建结果。

完整技术映射、代码片段与运行说明见 [`technical-delivery-guide.md`](./technical-delivery-guide.md)；录屏执行顺序见 [`demo-recording-script.md`](./demo-recording-script.md)。
